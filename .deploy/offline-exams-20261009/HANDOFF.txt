USER DECISION
Recover the same started attempt automatically on the same computer. Keep its original
deadline and durable answers; never give a fresh duration/grant. If time already expired,
freeze the saved answers and queue the final. New attempts still need a new admin grant.

IMPLEMENTED
- Download/persist all necessary questions and PDFs before Start. Incomplete preparation
  retries the same selected material. A stale prepared grant cannot block a new grant.
- Before Begin/Start, read-only GET /exam/offline/capabilities must return
  {"protocol":1,"grading_snapshots":true}. Old backend is rejected before spending access.
- AES-256-GCM local envelopes; per-file key protected by Windows Electron safeStorage.
  Versioned atomic fsync checkpoints with same-revision backup; no plaintext fallback.
- Local per-answer checkpoints and periodic clock checkpoint. Wall/monotonic high-water
  countdown, fixed server deadline, conservative request-delay accounting. Active recovery
  needs neither account-token refresh nor a new server start. Missing local PDF blocks
  editing without stopping the deadline; expired recovery does not need the PDFs.
- Completion freezes a durable immutable final before unlock/network. Pending outbox
  survives process restart and retries byte-identical data with an exact-attempt capability.
  Server receipt UUID, stage/grant, session/project, candidate and grade fields are checked.
  Duplicate requests return the same server receipt and do not create duplicate results.
- Server-only immutable grading snapshots captured at successful Begin/Start. Subsequent
  answer-key/text changes do not alter that attempt's score. Pending whole-project/session
  deletion guarded. Explicit account deletion remains authority revocation.
- Bounded recording chunks are fsynced to Desktop/GIPC_Recordings, then assembled;
  source segments retained. Capture startup/stop bounded; late callbacks cannot restart a
  finished exam. Disk/capture errors are visible. Unfinished recording metadata remains
  visible in the home dashboard even after answer acknowledgment and app restart.
- Duration-aware disk readiness estimate, trusted local top-frame IPC only, restricted
  navigation/media origins, update installation blocked while work is unfinished.
- Responsive recovery/outbox dashboard with usable controls and scrolling at 800x600.

OPERATIONAL LIMITS (DO NOT OVERCLAIM)
- During offline execution the server cannot know live progress; admin state catches up on
  final upload. No Internet required for active answers/materials, but initial authorization
  and receiving the final grade need a reachable compatible server.
- Do not edit questions/options/answer keys/project PDFs/regulations BETWEEN material
  preparation/download and Start. Grading snapshot freezes at Start, not during download.
  If contents changed during preparation, reprepare; automatic content-version handshake
  for this narrow pre-start interval is not implemented.
- Offline finish time is a client assertion, not cryptographic proof. Managed/supervised
  workstations are assumed. Local OS admin/tampering, intentional clock rollback while
  powered off and physical disk loss cannot be fully prevented by this implementation.
- Low-space readiness estimates capacity; it does not reserve disk blocks. On actual disk
  write failure, the latest unsaved chunk can exist only in RAM. Do not silently treat a
  recording warning as a successful full video; invigilator must inspect/recover it before
  closing. Persisted chunks/answers remain separate and recordings are not auto-uploaded.
- No automatic deletion of exam evidence or old recordings. Local store has bounded
  attempt/material limits; future supervised retention/archival policy may be needed for
  long-term high-volume workstations. No new server backup clutter created.
